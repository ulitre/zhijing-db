# 部署与交付

## 1. 部署 API 到 Railway

Railway CLI 可直接上传本地源码，不要求 GitHub 仓库。项目根目录已经提供 `Dockerfile`，在仓库根目录执行：

```powershell
npx @railway/cli@latest login
npx @railway/cli@latest up --new --name zhijing-db-api
npx @railway/cli@latest domain
```

在 Railway 服务变量中配置：

- `DEEPSEEK_API_KEY`：可选；不配置时使用确定性本地生成器。
- `DEEPSEEK_MODEL`：可选，默认 `deepseek-flash`。
- `DATABASE_URL`：可选；不配置时使用进程内演示数据。
- `ADMIN_SECRET`：仅在使用管理接口时配置。

Railway 会自动注入 `PORT`。部署后访问 `https://你的-api域名/health`，确认状态为 `ok`、课程节点为 45、智能体为 12。

当前生产 API：<https://zhijing-db-api-production.up.railway.app>  
健康检查：<https://zhijing-db-api-production.up.railway.app/health>

## 2. 使用 Vercel 部署 Web 客户端

发布前显式设置生产 API 地址；`EXPO_PUBLIC_*` 会在导出时写入 Web 包，不能沿用本地 `.env` 中的 `localhost`：

```powershell
Set-Location apps/client
$env:EXPO_PUBLIC_API_URL = 'https://zhijing-db-api-production.up.railway.app'
npx expo export --platform web --clear
npx vercel env add EXPO_PUBLIC_API_URL production
npx vercel deploy --prod --yes
```

Vercel 会返回 `vercel.app` 生产地址。发布前先在项目根目录运行 `pnpm check:delivery`，确认导出包包含生产 HTTPS API 且不含本机 API 地址；部署后按测试手册走完登录、路径、资源、导师和 SQL 沙箱流程。

## 3. 生成 Android APK

确认 `apps/client/eas.json` 中 `preview.env.EXPO_PUBLIC_API_URL` 为真实 API 地址，再执行：

```powershell
Set-Location apps/client
npx eas-cli@latest login
npx eas-cli@latest build --platform android --profile preview
```

`preview` 配置会生成内部测试 APK。下载后安装到 Android 真机，重点验证网络请求、输入框、SQL 结果横向滚动和底部导航。

构建前可执行完整交付门禁：

```powershell
Set-Location ../..
pnpm check:delivery
```

运行该命令前同样需要设置 `EXPO_PUBLIC_API_URL` 为生产 API。该命令会在常规 Lint、类型检查、测试和 Web 导出后，额外确认 API/Web/EAS 配置文件、Android 包名、APK 构建类型以及线上 API 地址均已就绪。
