# 测试与验收手册

## 自动化检查

在仓库根目录执行：

```powershell
pnpm typecheck
pnpm test
pnpm --filter client build
```

自动化测试覆盖：

- 45 个知识节点数量及前置关系完整性。
- 掌握度上升/下降算法及三类画像的路径差异。
- API 健康状态、危险 SQL 拒绝、真实 sql.js Worker 查询。
- LangGraph 资源工作流完成六个阶段并通过 ReviewAgent。

## 手工演示脚本

1. 在登录页依次查看三类学习者，选择“基础薄弱型”。
2. 进入首页，说明目标、掌握度和代理协作轨迹。
3. 打开“路径”，展示知识断点、前置关系和推荐资源。
4. 打开“资源”，点击“SQL 实操”，展示个性化生成结果。
5. 打开“导师”，提问“候选键和主键有什么区别？”，展示课程内回答和引用。
6. 向导师提一个课程外问题，展示范围拒答。
7. 调用 `/api/sql/run` 执行三表联查，再用 `ATTACH DATABASE` 展示安全拒绝。
8. 切换到实践型用户，比较路径和资源形式。
9. 从“我的”点击“切换学生类型”，确认返回学生选择页并可再次进入首页。
10. 在 AI 辅导输入“事物的四大特性”，确认系统按“事务的四大特性”解释 ACID，且发送后输入框清空。
11. 连续点击不同资源类型，确认立即出现“生成中”反馈，接口较慢时页面仍可操作。

## 已知边界

- 生产 API 已部署在 Railway，模型配置为 DeepSeek；当前线上数据库为进程内存模式，服务重启后数据会重置。
- 本地未配置模型服务时，资源内容由确定性生成器产生，便于复现实验。
- 真机不能用 `localhost` 访问电脑 API；最终 APK 的 EAS `preview` 环境配置为 HTTPS 生产 API 地址，仍需在真机运行中确认。
- 最终 APK 已由 EAS `preview` 构建并下载到 `deliverables`。真机安装、移动网络交互以及真实用户试用尚未完成，不能据此声称已通过真机或教学效果验证。
